### 1. 前端 API 导入错误

**问题**: `The requested module '/src/services/api/contract-templates.ts' does not provide an export named 'get'`

**根本原因**:
- Orval 生成的 API 文件有两种命名模式
- 旧模式导出 `getAuthApi`, `getCustomers` 等
- 新模式导出 `getProductPackages`, `getContractTemplates` 等
- `index.ts` 错误地尝试导入 `get` 别名

**解决方案**:
```typescript
// ❌ 错误
import { get as getProductPackagesApi } from './product-packages'

// ✅ 正确
import { getProductPackages } from './product-packages'
```

**文件**: `frontend/src/services/api/index.ts`

**Commit**: `bfbefff` - fix: 修复前端 API 导入、Redis 配置和 Context Provider 问题

---

### 2. 后端 Redis 配置问题

**问题**: `AggregateError [ECONNREFUSED]: connect ECONNREFUSED 127.0.0.1:6379`

**根本原因**:
- `automation.module.ts` 直接使用 `process.env`
- 没有通过 `ConfigService` 读取环境变量
- 导致远程 Redis 配置无法正确加载

**解决方案**:
```typescript
// ❌ 错误
BullModule.forRoot({
  connection: {
    host: process.env.REDIS_HOST || 'localhost',
    port: parseInt(process.env.REDIS_PORT || '6379', 10),
  },
})

// ✅ 正确
BullModule.forRootAsync({
  imports: [ConfigModule],
  inject: [ConfigService],
  useFactory: (configService: ConfigService) => ({
    connection: {
      host: configService.get<string>('REDIS_HOST', 'localhost'),
      port: configService.get<number>('REDIS_PORT', 6379),
      password: configService.get<string>('REDIS_PASSWORD'),
      db: configService.get<number>('REDIS_DB', 0),
    },
  }),
})
```

**文件**: `backend/src/modules/automation/automation.module.ts`

**关键学习**:
- NestJS 中必须使用 `ConfigService` 读取环境变量
- 直接使用 `process.env` 会导致环境变量无法正确加载
- 异步配置模块需要使用 `forRootAsync` + `useFactory`

### 3. Users Context Provider 错误

**问题**: `useUsers has to be used within <UsersContext>`

**根本原因**:
- `Users` 组件缺少 `<UsersProvider>` 包裹
- `UsersPrimaryButtons` 组件使用了 `useUsers()` hook

**解决方案**:
```typescript
// ❌ 错误
export function Users() {
  return (
    <>
      <Header>...</Header>
      <Main>
        <UsersPrimaryButtons />  {/* ❌ 没有 Provider */}
      </Main>
    </>
  )
}

// ✅ 正确
export function Users() {
  return (
    <UsersProvider>
      <Header>...</Header>
      <Main>
        <UsersPrimaryButtons />  {/* ✅ 在 Provider 内 */}
      </Main>
    </UsersProvider>
  )
}
```

**文件**: `frontend/src/features/users/index.tsx`

**关键学习**:
- React Context 必须用 Provider 包裹子组件
- Hook 只能在对应的 Provider 内部使用
- 参考其他页面（Tasks）的正确模式

### 4. API 响应数据处理错误

**问题**: `Query data cannot be undefined`

**根本原因**:
- `api-client.ts` 的响应拦截器已自动提取 `data` 字段
- Hook 中再次访问 `response.data` 导致访问 `undefined`

**解决方案**:
```typescript
// ❌ 错误
const response = await usersControllerFindAll(params)
return response.data  // data 已被提取，这里是 undefined

// ✅ 正确
return await usersControllerFindAll(params)  // 直接返回
```

**文件**: `frontend/src/features/users/hooks/use-users.ts`

**关键学习**:
- 理解 axios 拦截器的工作流程
- Orval 的 `customInstance` 返回的是已处理的数据
- 不要重复访问已被提取的字段

### 3. Orval API 响应处理

**问题**: `response.data` 访问导致 undefined

**正确模式**:
```typescript
// api-client.ts 拦截器已自动提取 data
axiosInstance.interceptors.response.use(
  (response) => {
    const responseData = response.data as any
    if (responseData && typeof responseData === 'object' && 'data' in responseData) {
      response.data = responseData.data  // 自动提取
    }
    return response
  },
)

// ✅ Hook 中直接返回
return await apiCall(params)  // 不要访问 .data
```

**适用场景**:
- 所有 Orval 生成的 API 调用
- TanStack Query 的 queryFn
- Mutation 的 mutationFn

```typescript
// 智能识别响应类型
const isPaginatedResponse =
  'data' in responseData &&
  ('total' in responseData || 'page' in responseData)

const isStandardResponse =
  'success' in responseData &&
  'data' in responseData

}
```
