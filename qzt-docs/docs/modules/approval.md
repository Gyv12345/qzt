# 审批中心

审批中心是企智通平台的统一流程引擎，为 CRM 合同、PSI 采购销售单、HRM 请假加班、财务报销等各类业务提供标准化、可视化的审批能力。管理员通过**可视化流程设计器**拖拽配置审批流，业务系统提交申请后自动按既定规则流转，审批结果实时回写业务状态，全程支持消息通知。

## 核心能力

| 能力 | 说明 |
|------|------|
| 可视化流程设计 | 拖拽式节点编排，所见即所得 |
| 多级审批 | 支持任意层级的多级审批链 |
| 条件分支 | 根据金额、部门等条件走不同分支 |
| 会签 / 或签 / 依次审批 | 同一节点多审批人的协同方式 |
| 操作灵活 | 同意、驳回、退回、加签、转办 |
| 业务联动 | 审批通过自动更新业务状态 |
| 消息通知 | 全流程实时推送 |

## 可视化流程设计器

审批流的编排通过浏览器端的**可视化设计器**完成，无需任何代码，管理员即可配置出符合企业实际管理要求的审批流程。

### 设计器特性

- **拖拽编排**：从左侧节点面板拖入「审批节点」「条件分支」「抄送节点」到画布；
- **连线自由**：节点之间通过连线串联，支持条件分支的多出口；
- **实时校验**：保存时自动校验流程完整性（是否有环、是否可达、是否缺失审批人）；
- **版本管理**：流程修改后发布新版本，进行中的审批仍走旧版本，新发起的走新版本；
- **预览测试**：可模拟一次申请，预览流程的实际走向。

### 节点类型

设计器中可用的节点类型如下：

| 节点 | 作用 |
|------|------|
| **发起人节点** | 流程起点，定义谁能发起、表单字段 |
| **审批节点** | 由指定审批人进行审批操作 |
| **条件分支** | 根据表单字段值走不同路径（如金额 > 10万 走总监审批） |
| **抄送节点** | 不需要审批，仅通知相关人员 |
| **结束节点** | 流程终点 |

### 条件分支

条件分支是审批流「智能化」的关键，典型应用：

- **金额条件**：合同金额 ≤ 5万 部门经理审批；> 5万 需总经理加签；
- **部门条件**：销售部走 A 流程，技术部走 B 流程；
- **类型条件**：采购单 vs 销售退货走不同审批人；
- **多条件组合**：支持 AND / OR 组合条件。

## 多审批人协同方式

当一个审批节点配置了多个审批人时，可通过以下三种方式定义协同规则：

### 会签（AND）

节点上的**所有审批人**都必须同意，该节点才算通过。任一人驳回则整单驳回。

- 适用场景：重要合同需要法务、财务、业务三方共同确认；
- 特点：必须全员同意，缺一不可。

### 或签（OR）

节点上的审批人中**任意一人**同意，该节点即视为通过。

- 适用场景：多名同级销售经理，谁在线谁先批；
- 特点：抢批模式，效率最高。

### 依次审批

审批人**按顺序**逐个审批，前一人通过后才流转给下一人。

- 适用场景：组长 → 部门经理 → 总监的逐级上报；
- 特点：层级分明，符合传统科层制。

## 审批人类型

审批节点的审批人可以通过以下方式指定：

| 类型 | 说明 | 示例 |
|------|------|------|
| **指定成员** | 固定选择具体的用户 | 张三、李四 |
| **部门负责人** | 自动解析申请人所在部门的负责人 | 申请人所在部门的 manager 字段 |
| **角色** | 选择某个角色，该角色下所有用户均可审批 | 「财务主管」角色下的所有用户 |
| **发起人自选** | 发起时由申请人选择审批人 | 临时指定项目对接人 |
| **上级** | 沿组织架构逐级向上 | 申请人的 N 级上级 |

:::tip 部门负责人自动解析
选择「部门负责人」类型时，系统会根据**申请人**所在部门，自动查找该部门的负责人字段作为审批人。这种动态指派方式避免了人员变动时需要频繁修改流程配置的问题。
:::

## 审批操作

审批人在待办中打开审批单后，可执行以下操作：

| 操作 | 说明 |
|------|------|
| **同意** | 通过当前节点，流转到下一节点（或结束） |
| **驳回** | 直接驳回至发起人，流程终止，业务状态回滚 |
| **退回** | 退回到指定历史节点（如退回给申请人修改），可继续审批 |
| **加签** | 临时增加一名审批人（前加签 / 后加签 / 并加签） |
| **转办** | 将审批任务转交给他人代为审批 |
| **撤回** | 发起人在审批中可主动撤回申请 |

### 加签详解

加签是应对突发情况的灵活机制：

- **前加签**：在当前审批人之前，先由加签人审批；
- **后加签**：当前审批人通过后，再由加签人审批；
- **并加签**：与当前审批人并行审批（相当于临时会签）。

## 审批通过自动更新业务状态

审批并非孤立动作，其结果会**自动回写**到业务对象，实现流程与业务的联动：

| 业务场景 | 审批通过后的动作 |
|---------|----------------|
| CRM 合同审批 | 合同状态 → 已签订 |
| CRM 大额折扣审批 | 商机折扣生效 |
| PSI 采购单审批 | 采购单状态 → 已审核，可入库 |
| PSI 销售单审批 | 销售单状态 → 已审核，可出库 |
| HRM 请假审批 | 自动扣减假期余额 |
| HRM 加班审批 | 计入考勤汇总 |

这种「**审批即业务**」的设计，避免了审批通过后还需要人工去业务系统二次操作的繁琐，保证数据一致性。

## 消息通知

审批全流程配套消息通知，确保相关人员第一时间知情：

- **待办通知**：审批人收到待办时，推送站内信 / 企业微信；
- **结果通知**：发起人收到审批结果（通过 / 驳回 / 退回）；
- **抄送通知**：抄送节点通知相关人员知会；
- **催办通知**：超时未审批时自动催办；
- **撤回通知**：发起人撤回时通知所有已审批人。

通知渠道可在系统配置中开启/关闭，支持站内信、企业微信（含 SSE 实时推送）等多通道。

| [HRM](./hrm) | 请假、加班、出差、入职、离职审批 |
