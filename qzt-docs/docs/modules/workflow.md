# 自动化工作流（workflow）

workflow 是平台的 **n8n 式自动化引擎**：在 Admin 的可视化画布设计器中编排「触发器 → 动作 → 条件分支」的工作流，保存后即可被手动运行、定时调度或业务事件自动触发。它把散落在各模块的重复操作收敛成可复用的自动化流——例如「新线索入库自动发通知给负责人」「审批通过后自动更新客户等级」。

## 核心概念

### 画布图（Graph）

工作流以 JSON 图存储，节点分三类：

| 节点类型 | 说明 |
|---------|------|
| `TRIGGER` | 入口节点，承载触发配置（与工作流的触发类型对应） |
| `ACTION` | 动作节点，执行一个具体动作（见下文动作目录） |
| `CONDITION` | 条件节点，多条出边按顺序对应各分支，`when` 为空的边是兜底分支 |

连线（link）将节点串成执行路径；保存时后端做图校验（结构、动作合法性、触发配置合法性），非法图直接拒绝入库。

### 触发类型

| 类型 | 说明 |
|------|------|
| `MANUAL` | 手动运行（Admin 页面「运行」按钮或接口触发）；允许对未启用的工作流做测试运行 |
| `CRON` | 定时调度，6 段式 cron（秒 分 时 日 月 周）；使用 workflow 专属调度器（robfig/cron），**不混入**「定时任务」模块的 sys_job 体系，定义保存/启停/删除时自动重载注册 |
| `EVENT` | 业务事件触发，事件名必须在事件目录内（见下文） |

### 事件目录

事件经进程内 `xevent` 总线订阅分发：业务点发布事件 → 订阅器异步匹配「已启用的 EVENT 工作流」→ 逐个执行，不阻塞事件发布方主链路。

| 事件 | 名称 | 触发时机 |
|------|------|---------|
| `approval.finished` | 审批完成 | 合同/请假/报销等审批流结束时 |
| `approval.task.assigned` | 审批待办产生 | 审批节点到达新审批人时 |
| `crm.lead.created` | 新线索入库 | 线索创建（含公海导入、抖音线索同步）后 |
| `crm.customer.created` | 新客户建档 | 客户创建后 |
| `crm.payment.created` | 回款登记 | 合同回款登记后 |
| `psi.sales_order.stock_out` | 销售出库 | 销售订单出库后 |

:::info 扩展事件
新业务事件在代码内发布到 `xevent` 总线并登记 `EventCatalog` 后即可选作触发器，无需改引擎。
:::

## 动作目录

| 动作 | 说明 |
|------|------|
| `notify` 发送通知 | 站内信 + SSE 实时推送 + 企微/服务号，一次调用全通道（演示模式下自动降级为站内信） |
| `field_update` 更新字段 | 按服务端白名单更新业务表字段：`crm_lead.status`、`crm_customer.level/status`（字段名是服务端可信代码，禁拼客户端输入，扩白名单需评审） |
| `http` HTTP 请求 | 出站调用（GET/POST），10 秒超时；支持自定义 header、模板渲染 body，可选 HMAC 签名头（`X-QZT-Signature: t=<ts>,v1=<hex>`，与开放平台 Webhook 同风格） |
| `llm` AI 生成 | 调内部 [LLM 网关](/modules/ai)生成文本，可用于跟进建议、摘要等，输出可注入后续动作 |

### 模板渲染

动作配置中的字段支持 `{{payload.xxx}}` 模板占位符，取值来自触发上下文（事件负载 / 手动传入的参数），执行时逐节点渲染。例如事件触发时 `{{payload.lead_id}}` 即新线索的 ID。

## 执行引擎

- **同步执行**：一次运行完整跑完画布路径，返回执行记录；
- **节点轨迹**：每个节点的输入输出记录在 `node_trace` 中，Admin 可逐步查看执行轨迹定位问题；
- **防重入**：同一工作流同时只允许一个执行实例，重复触发直接跳过（定时与事件触发均安全）；
- **耗时统计**：执行记录带总耗时（`cost_ms`）与错误摘要（截断保存）；
- **失败重试**：失败 run 可一键重试；
- **运行统计**：工作流定义维护最近运行时间与累计运行次数。

## 接口清单

### 工作流定义

| 接口 | 方法 | 说明 |
|------|------|------|
| `/workflow/definitions` | GET / POST | 定义分页列表 / 新增（校验触发配置与画布图） |
| `/workflow/definitions/:id` | GET / PUT / DELETE | 详情 / 编辑（保存后重载调度）/ 删除 |
| `/workflow/definitions/:id/run` | POST | 手动运行一次（同步返回执行记录） |
| `/workflow/definitions/:id/enable` | PUT | 启用 / 停用 |
| `/workflow/events` | GET | 可用事件目录（设计器触发器面板用） |

### 执行记录

| 接口 | 方法 | 说明 |
|------|------|------|
| `/workflow/runs` | GET | 执行记录分页（状态 / 耗时 / 节点轨迹） |
| `/workflow/runs/:id` | GET | 执行详情（含每节点输入输出轨迹） |
| `/workflow/runs/:id/retry` | POST | 重试一次失败的执行 |
| `/workflow/runs/:id` | DELETE | 删除执行记录 |

## 与其他模块的联动

| 联动模块 | 联动场景 |
|---------|---------|
| [OA](/modules/oa) | `notify` 动作复用站内信全通道发送 |
| [CRM](/modules/crm) | 线索/客户/回款事件触发；`field_update` 更新线索状态与客户级别 |
| [审批中心](/modules/approval) | 审批完成/待办事件触发 |
| [PSI 进销存](/modules/psi) | 销售出库事件触发 |
| [AI 业务系统](/modules/ai) | `llm` 动作走统一 LLM 网关；工作流也可通过 MCP 工具被 AI 编排运行 |
