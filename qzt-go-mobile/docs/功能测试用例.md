## 1. 测试环境与前置条件

### 1.1 环境准备

| 项目 | 要求 |
|------|------|
| 后端服务 | `qzt-go-server` 运行在 `localhost:9000`，数据库已初始化种子数据 |
| 移动端 | `cd qzt-go-mobile && pnpm dev`，访问 `http://localhost:5174` |
| 浏览器 | Chrome DevTools 移动端模拟（推荐 iPhone 12 Pro 视口）或真机扫码 |
| 网络 | 后端可连通；如测试企微绑定需公网可达的回调地址 |

### 1.2 测试账号

| 角色 | 账号 | 密码 | 说明 |
|------|------|------|------|
| 超级管理员 | `admin` | `shijie123`（生产）/ `admin123`（本地种子） | 拥有全部权限，权限码含 `*` 通配 |

## 2. 通用测试模式（跨页面复用）

以下模式适用于**所有列表页**和**所有表单页**，执行各模块测试时无需逐条重复，但需确认目标页面遵循这些模式。

### 2.1 列表页通用模式

涉及页面：customer / lead / opportunity / contract / product / ticket / contact / expense / trip / loan / work-log / schedule / meeting / employee / department / position / performance / job / stock / movement / asset / supplier / warehouse / news / notice / kb / approval / finance 各列表 / psi 各列表 等。

| 编号 | 用例 | 步骤 | 预期结果 | 优先级 |
|------|------|------|----------|--------|
| GP-L01 | 首次加载 | 进入列表页 | 自动加载第 1 页数据（page_size=20），显示 SpinLoading 加载态 | P0 |
| GP-L02 | 下拉刷新 | 列表顶部下拉 | 触发 PullToRefresh 动画，重置到第 1 页并刷新数据 | P0 |
| GP-L03 | 无限滚动 | 数据 >20 条时滚动到底部 | 自动加载下一页，拼接至列表尾部 | P0 |
| GP-L04 | 加载边界 | 持续滚动直到数据加载完毕 | `hasMore=false`，底部不再触发请求，InfiniteScroll 消失 | P1 |
| GP-L05 | 搜索过滤 | 在 SearchBar 输入关键词 | 列表按关键词过滤并重置到第 1 页 | P0 |
| GP-L06 | 空列表 | 搜索无结果 / 无数据 | 展示空状态提示（ErrorBlock 或空文案） | P1 |
| GP-L07 | 网络异常 | 断开后进入/刷新列表 | Toast 提示网络错误，不崩溃；恢复后下拉刷新可恢复 | P1 |

### 2.2 表单页通用模式（FormSheet）

涉及页面：几乎所有带「新增/编辑」的页面。

| 编号 | 用例 | 步骤 | 预期结果 | 优先级 |
|------|------|------|----------|--------|
| GP-F01 | 必填校验 | 新增表单不填必填字段，直接提交 | 表单校验拦截，Toast/行内提示必填项，不发起请求 | P0 |
| GP-F02 | 新增成功 | 填写合法数据并提交 | Toast 成功提示 → 表单关闭 → 列表自动刷新，新记录出现在顶部 | P0 |
| GP-F03 | 编辑回填 | 点击列表项编辑 | FormSheet 以 `initialValues` 预填当前数据，修改后提交成功更新 | P0 |
| GP-F04 | 数字字段 | 填写数字类型字段（金额/数量等） | 提交时正确解析为数值类型，非数字输入被拦截 | P1 |
| GP-F05 | 选择器字段 | 使用 select / select-multiple / Selector | 单选提交标量值；多选提交数组值，组件内部已展开为单值 | P1 |
| GP-F06 | 日期选择器 | 使用 date / datetime 字段 | DatePicker 弹出，选择后提交格式化的日期/时间字符串 | P1 |
| GP-F07 | 提交按钮 | 点击底部提交按钮 | **必须通过 `onClick={() => form.submit()}` 触发**，不能用 `type="submit"` | P0 |

### 2.3 删除通用模式

| 编号 | 用例 | 步骤 | 预期结果 | 优先级 |
|------|------|------|----------|--------|
| GP-D01 | 确认弹窗 | 点击删除按钮 | 弹出 Dialog.confirm 二次确认 | P0 |

## 3. 通用基础组件测试

### 3.1 请求封装（request.ts）

| 编号 | 用例 | 前置条件 | 步骤 | 预期结果 | 优先级 |
|------|------|----------|------|----------|--------|
| REQ-01 | 成功响应解包 | 已登录 | 触发任意正常 API 调用 | 后端返回 `{code:0, data:...}` 被自动解包，service 层直接拿到 `data` | P0 |
| REQ-02 | 业务错误提示 | 已登录 | 触发返回 `{code:非0, msg:"xxx"}` 的接口 | Toast 显示失败图标 + 错误消息，Promise reject | P0 |
| REQ-03 | 401 自动刷新 | token 过期 | 触发接口返回 401 | 自动调用 `POST /system/auth/refresh`，成功后重试原请求，用户无感知 | P0 |
| REQ-04 | 401 刷新失败 | refresh token 也过期 | 触发接口返回 401，刷新也失败 | Toast「登录已过期」→ 跳转 `/login` | P0 |
| REQ-05 | 403 权限拒绝 | 已登录无权限 | 触发无权限接口 | Toast「没有操作权限」 | P0 |
| REQ-06 | 网络错误 | 断网 | 触发任意请求 | Toast 显示网络错误信息，不白屏 | P1 |
| REQ-07 | Authorization 注入 | 已登录 | 检查请求头 | 所有受保护接口请求头携带 `Authorization: Bearer <accessToken>` | P0 |
| REQ-08 | 并发刷新单飞 | 多个请求同时 401 | 同时发起多个过期请求 | refresh 只调用一次，所有请求排队等待后重试（单飞机制） | P1 |

### 3.2 鉴权与权限（auth store + RequireAuth）

| 编号 | 用例 | 前置条件 | 步骤 | 预期结果 | 优先级 |
|------|------|----------|------|----------|--------|
| AUTH-01 | 未登录拦截 | 未登录 | 直接访问 `/customer` 等受保护路由 | 自动重定向到 `/login` | P0 |
| AUTH-02 | 刷新后恢复 | 有 token 但 `userLoaded=false` | 刷新页面 | 显示 SpinLoading → 调用 `fetchUserInfo()` 加载用户信息 → 正常进入页面 | P0 |
| AUTH-03 | 用户信息加载失败 | token 无效 | 刷新页面 | 显示「用户信息加载失败」重试界面 | P1 |
| AUTH-04 | 权限按钮隐藏 | 普通销售账号（无 `crm:customer:edit`） | 进入客户详情 | 「编辑」按钮不显示 | P0 |
| AUTH-05 | 通配权限 | admin 超管（权限含 `*`） | 进入任意详情页 | 所有操作按钮可见 | P0 |
| AUTH-06 | 深链接恢复 | 已登录 | 直接粘贴 `/customer/123` 到地址栏 | RequireAuth 加载用户信息后正确进入详情页 | P1 |

### 3.3 无限滚动 Hook（useInfiniteList）

| 编号 | 用例 | 步骤 | 预期结果 | 优先级 |
|------|------|------|----------|--------|
| IL-01 | 挂载自动加载 | 进入任意列表页 | useEffect 自动触发第 1 页加载，不依赖 InfiniteScroll 的 IntersectionObserver | P0 |
| IL-02 | 防重复加载 | 快速多次滚动到底部 | `loadedRef` 防护，不发起重复请求 | P1 |

## 12. 已知缺陷与边界场景

### 12.1 已知代码缺陷（需验证是否复现）

| 编号 | 缺陷描述 | 涉及文件 | 复现步骤 | 预期修复方向 | 优先级 |
|------|----------|----------|----------|-------------|--------|
| BUG-01 | **请假详情大数据量丢失** | `hrm/leave/detail.tsx` | 请假记录 >100 条时，详情通过 `listLeaves(page_size:100)` 查找 by id，超过 100 条的记录无法打开详情 | 改用专用 GET 接口或增大 page_size | P1 |
| BUG-02 | **报销搜索语义混淆** | `expense/index.tsx` | SearchBar 的 placeholder 是「搜索审批状态」，实际做的是 approval_status 过滤而非关键词搜索 | 改用下拉筛选审批状态或明确文案 | P2 |

### 12.2 边界与异常场景

| 编号 | 场景 | 步骤 | 预期结果 | 优先级 |
|------|------|------|----------|--------|
| EDGE-01 | 不存在的 ID | 访问 `/customer/99999999` | ErrorBlock 展示，不白屏不崩溃 | P0 |
| EDGE-02 | 权限不足操作 | 无权限用户尝试操作（直接调 API） | 后端 403，Toast「没有操作权限」 | P0 |
| EDGE-03 | 并发操作 | 两人同时编辑同一条客户 | 后提交者覆盖或后端乐观锁拒绝 | P2 |
| EDGE-04 | 超长文本 | 表单输入超长字符串 | 前端/后端正确截断或校验，不崩溃 | P2 |
| EDGE-05 | 特殊字符 | 名称含 `<script>` 等 XSS payload | 后端存储/渲染时转义，不执行 | P0 |
| EDGE-06 | 弱网加载 | 慢速网络下加载列表 | SpinLoading 持续显示，超时后可重试 | P1 |
| EDGE-07 | 返回导航 | 从详情页返回列表 | 列表保持之前的滚动位置和筛选状态（或合理刷新） | P1 |
| EDGE-08 | FloatingBubble 可见性 | 任意有 FloatingBubble 的页面 | 按钮在右下角可见（依赖 global.css 的 `--initial-position-bottom/right` 默认值） | P0 |
